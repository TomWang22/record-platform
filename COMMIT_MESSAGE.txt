## k6 HTTP/3 Toolchain Implementation

### Custom k6 Binary with HTTP/3 Extension
- **Built**: Custom k6 binary using xk6 with HTTP/3 extension
- **Extension**: `github.com/record-platform/xk6-http3` (local development)
- **Library**: Uses `quic-go` for HTTP/3 (QUIC) support
- **Binary Location**: `.k6-build/bin/k6-http3`
- **Build Script**: `scripts/build-k6-http3.sh`
- **Status**: ✅ Extension builds and loads successfully

### Extension Features
- **HTTP/3 Client**: Full QUIC implementation using quic-go
- **Methods**: GET and POST implemented
- **Timeouts**: Increased to 60s for QUIC handshake (from 30s)
- **QUIC Config**: HandshakeIdleTimeout 10s, MaxIdleTimeout 60s, KeepAlive 10s
- **TLS**: Configurable insecureSkipTLSVerify for dev environments

### Current Limitation
- ⚠️ **NodePort UDP Routing**: HTTP/3 (QUIC) connection times out via NodePort (30443)
- **Root Cause**: External k6 runs outside Kind cluster, NodePort UDP routing may not work correctly for QUIC
- **Workaround**: Use curl-based HTTP/3 testing (`scripts/test-microservices-http2-http3.sh`) which runs inside Kind node network namespace

### Documentation
- **Status Document**: `test-results/K6_HTTP3_TOOLCHAIN_STATUS_12-22_tom.md`
- **README.md**: Updated with toolchain status and workaround
- **ENGINEERING.md**: Updated with extension implementation details

## Rotation Chaos Workflow Fix

### Strict TLS Certificate Mount Fix
- **Issue**: CA certificate not mounted correctly in k6 job, causing strict TLS failures
- **Fix**: Updated `scripts/run-k6-chaos.sh` to use `subPath` for CA certificate mount
- **Change**: Mount CA certificate at `/etc/ssl/certs/ca.crt` using `subPath: ca.crt`
- **Impact**: k6 can now find and use CA certificate for strict TLS verification during rotation
- **Documentation**: `test-results/ROTATION_CHAOS_STRICT_TLS_FIX_12-22_tom.md`
