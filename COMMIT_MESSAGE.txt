## Recovery Procedures

### Service Recovery
1. **Check service status**: `kubectl -n record-platform get pods`
2. **Check service logs**: `kubectl -n record-platform logs -l app=<service-name> -c app --tail=100`
3. **Restart service**: `kubectl -n record-platform rollout restart deployment/<service-name>`
4. **Verify rollout**: `kubectl -n record-platform rollout status deployment/<service-name> --timeout=90s`

### Database Recovery
1. **Check disk space**: `df -h` and `docker system df`
2. **Cleanup Docker**: `docker system prune -a --volumes`
3. **Cleanup Kubernetes**: `kubectl -n record-platform delete pvc --all` (if safe)
4. **Restart databases**: `docker-compose restart postgres-*`

### Linkerd Recovery
1. **Check Linkerd status**: `linkerd check`
2. **Fix CoreDNS**: `kubectl -n kube-system rollout restart deployment/coredns`
3. **Re-enable injection**: `kubectl annotate namespace record-platform linkerd.io/inject=enabled --overwrite`
4. **Restart deployments**: `kubectl -n record-platform rollout restart deployment --all`

### API Gateway Recovery
1. **Check proxy errors**: `kubectl -n record-platform logs -l app=api-gateway -c app | grep -E "proxy error|502|upstream"`
2. **Check Redis connection**: `kubectl -n record-platform logs -l app=api-gateway -c app | grep -E "redis"`
3. **Restart gateway**: `kubectl -n record-platform rollout restart deployment/api-gateway`
4. **Verify routes**: Test with `curl` or test script
