# Cert Lifecycle: CA → Leaf → Secret

Single source of truth for TLS in preflight and services. See also Runbook (reissue, curl 60), and `scripts/reissue-ca-and-leaf-load-all-services.sh`.

## Flow

1. **CA** — `certs/dev-root.pem` (and optionally `certs/dev-root.key` for Kafka). Generated or re-used by reissue step 1.
2. **Leaf** — Server cert for record.local / SANs. Generated by reissue step 1; chained with CA.
3. **Secrets** — Kubernetes secrets updated by reissue step 2:
   * `record-local-tls` (ingress-nginx, record-platform): tls.crt (chain), tls.key
   * `dev-root-ca`: dev-root.pem
   * `service-tls` (record-platform): tls.crt, tls.key, ca.crt

## Guardrails (stabilization plan)

* **Idempotent** — Cert scripts can be re-run; they overwrite or patch, no implicit regeneration from stale state.
* **Secrets patched once per run** — Reissue step 2 does delete+create or patch in a single serialized pass; no overlapping secret churn.
* **Verify before load** — Preflight verifies Caddy strict TLS (no curl 60) before starting pgbench/k6 or suites.
* **Cert work never concurrent with load** — Phase B (cert) is separate from Phase C (load). No Service creation or scaling during cert issuance.

## Where certs are used

* **Caddy** — Mounts `record-local-tls` and `dev-root-ca`; serves HTTPS/HTTP3 for record.local.
* **Envoy (envoy-test)** — Mounts `envoy-service-tls` and `dev-root-ca` for gRPC TLS.
* **Services (auth, api-gateway, etc.)** — Mount `service-tls` and/or `dev-root-ca` for mTLS and upstream TLS.
* **Kafka** — `kafka-ssl-secret` (from dev-root-ca) for strict TLS :29093.
* **k6 / curl** — Use `certs/dev-root.pem` (SSL_CERT_FILE or --cacert) for strict TLS to Caddy.

## Reissue script steps (summary)

0. Preflight (kubeconfig, cluster reachable, namespaces).
1. Generate CA and leaf (on host).
2. Update secrets (record-platform + ingress-nginx); optionally via colima ssh to avoid tunnel burst.
3. Sync TLS to envoy-test.
4. Write certs to `certs/`.
5. Restart Caddy (rollout).
6. Ensure service-tls ready.
7. Restart service deployments.

Abort on first failure; retries are bounded and documented (see Runbook).
