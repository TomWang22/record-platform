# Under the Hood Analysis

**Date:** 2026-01-23  
**Status:** Comprehensive analysis of stability and strict TLS

## Root Causes of Instability

### 1. kubectl Port Mismatch ✅ FIXED
- **Issue**: Docker maps kind API server (6443) to dynamic host port
- **Symptom**: `kubectl cluster-info` fails with connection errors
- **Fix**: Auto-detect and update port in `ensure-api-server-ready.sh`
- **Permanent**: Script now fixes port every 5 attempts automatically

### 2. API Server Check Too Strict ✅ FIXED
- **Issue**: `kubectl cluster-info` fails but cluster is actually accessible
- **Symptom**: Tests fail before they start
- **Fix**: Multiple fallback methods:
  - Try `kubectl cluster-info` (primary)
  - Try `docker exec h3-control-plane kubectl get nodes` (fallback)
  - Try `kubectl get nodes` (less strict fallback)
- **Result**: Tests continue even if primary check fails

### 3. Pod Configuration Issues ⚠️ IDENTIFIED
- **api-gateway**: CreateContainerConfigError (likely missing secret/config)
- **listings-service**: CreateContainerConfigError (likely missing secret/config)
- **postgres**: CrashLoopBackOff (database startup issue)
- **Several services**: Running but not ready (health check failures)

## Rotation Suite Configuration

### CA Rotation
- Generates new CA certificate
- Updates `dev-root-ca` secret in both namespaces
- Includes overlap window for zero-downtime

### Leaf Rotation
- Generates new leaf certificate (signed by new CA)
- Includes SANs: `record.local`, `*.record.local`, `localhost`, ClusterIP FQDN, IPs
- Updates `record-local-tls` secret in both namespaces
- Restarts Caddy to pick up new certs

### Strict TLS During Rotation
- k6 tests use new CA certificate
- All requests verify certificate chain
- No `-k` flags used
- Certificate overlap window prevents downtime
